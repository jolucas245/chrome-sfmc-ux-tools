# Changelog

## [Unreleased]

### Added

- **Content Builder, a `<script>` that will be lost is underlined**: Marketing Cloud cuts JavaScript for the browser out of emails, email templates and content blocks when it saves them, the tag and what is in it, and still reports the save as done. The extension now underlines the opening tag of every such `<script>` and says so when you rest the mouse on it, with a link to the page on sfmc.guide that lists what is kept where.
    - **What the note also says:** after the save the editor may still show the tag although the stored content no longer has it, and `runat="server"` may just be missing if server-side JavaScript was meant.
    - **Error** in an email and an email template, also in a block you edit inside an email.
    - **Warning** in a content block on its own (HTML block, code snippet, free form, text block): it may have been meant for a CloudPage, but the block loses the script when it is saved all the same.
    - **Not marked:** server-side scripts (`<script runat="server">`), AMPscript in a script tag, and anything in CloudPages, which keeps scripts for the browser.
- **Content Builder, a warning for HTML tags typed into the text editor**: the **Content** tab of a free form block and a text block is a text editor, not a code editor. A tag typed there, such as `<script>` or `<div>`, is saved as plain text: readers see it as written, and code in it never runs. Marketing Cloud still reports the save as done.
    - **Underlined:** every piece of text that looks like an HTML tag gets a yellow wavy underline.
    - **A note above the editor** names the first such tag, says what happens to it and that HTML and code belong in the HTML Editor tab of the block, with a link to the page on sfmc.guide that lists what is kept where. The extension's icon in the note says under the mouse that the extension added it.
    - **Not marked:** formatting made with the editor's own buttons, comparisons such as `a < b`, and AMPscript in `%%[ ]%%` and `%%= =%%`.
    - **Only a warning:** saving works as before, and the extension adds nothing to the content.
    - The feature is always on and has no switch, and needs no new permission.
- **A wider menu in Email Studio**: the menu on the left of Email Studio was always 236 pixels wide, so long folder names were cut off. Now its right edge can be dragged.
    - **How:** a handle with a dotted grip between the menu and the content, in the place of the bar that collapsed the menu on a click. While it is dragged, a line shows where the edge will be, and the width changes once it is let go: Email Studio's tables lose their rows for a moment whenever they get less room, also when the window is made narrower. Double-click it for Email Studio's own width; with the keyboard, the arrow keys, **Home** and **End** change the width.
    - **Remembered:** the width is kept in Chrome's extension storage on this computer, for every tab and business unit, and a new width applies at once to the other open tabs. Email Studio's own width is not kept.
    - **Limits:** between 170 pixels and 60% of the window.
    - **Hiding and showing the menu:** the button above the menu, which hid it already, shows the icon of a side bar in place of the double arrow. A drag that ends left of 170 pixels hides the menu too, and the menu keeps the width it had. A hidden menu leaves a button with the same icon at the top left, which shows it again; it takes the place of Email Studio's thin bar for that.
    - The page loads two more files of the extension for this, the icons of these two buttons.
    - The extension runs one more script and a stylesheet in Email Studio's frame (`https://*.exacttarget.com/C12/Default.aspx`), where it ran already. It makes no request and needs no new permission. The feature is always on and has no switch.
- **Jump between the data extensions of a folder**: in Email Studio, opening another data extension of the same folder meant going back to the folder first. Now the name of an open data extension in the path above it, and a small arrow after it, list the others of its folder.
    - **What you see:** all data extensions of the folder, sorted by name, the open one in bold, with a search box on top. A click opens the data extension by Email Studio's own route, without loading the page again. The name in the path can be chosen with Tab and opened with **Enter** or **Space**; the arrow keys, **Enter** and **Esc** work in the list.
    - **How:** each time the list is opened, the Marketing Cloud page reads the open data extension (for its folder) and the data extensions of that folder from Marketing Cloud's documented REST API (`data/v1/customobjects`), through the page you are logged in to, 25 at a time and up to six pages at once. Only data extensions and filtered data extensions are kept, as in Email Studio's own list; the channels' own data extensions and Audience Builder's results, which the API also has in the folder, are left out. Only the id and the name of each are passed on to Email Studio's frame, through the background script, which takes the question from Email Studio's frame only.
    - **Limits:** no subfolders, and at most 1,000 data extensions; a folder with more says so.
    - The extension runs one more script and a stylesheet in Email Studio's frame (`https://*.exacttarget.com/C12/Default.aspx`) and one more script on the Marketing Cloud page, where it ran already. It needs no new permission. It uses what `deep-link-email-studio-page.js` tells about the open view, and its route to open one. The feature is always on and has no switch.
- **Search the records of a data extension on every field**: in Contact Builder, the **Records** tab of a data extension searched its primary key fields only, and not at all without a primary key. Now it searches any field.
    - **The menu lists every field:** primary key fields on top, marked with **(primary key)**, then all other fields from A to Z below a line.
    - **Without a primary key** the extension adds the menu that Marketing Cloud leaves out and switches the greyed-out search box on.
    - **How it searches:** values that start with your text, whatever their case. `%` stands for any text and `_` for one character. An apostrophe is treated like `_`.
    - **By type:** a date field takes a year, a month or a day (`2026`, `2026-01`, `2026-01-15`); a boolean field takes `true`, `false`, `1` or `0`; numbers are searched by their first digits.
    - **A hint where you type:** the search box says **Starts with… (% = any text)**, and the extension's icon next to it explains the rest when you rest the mouse on it.
    - **How:** a search on a primary key field stays Marketing Cloud's own request. Its search ignores other fields, so for those the extension sends the request to another address of Marketing Cloud that reads the rows of a data extension, through the page you are logged in to, and hands the answer to Marketing Cloud's own table. Nothing is written.
    - **Limits:** one field at a time, and such a search does not follow the column you sorted by.
    - The feature is always on and has no switch, and needs no new permission.
- **SQL query activity, mistakes underlined while you type**: the query editor of Automation Studio's SQL query activity shows what Marketing Cloud's own check finds, without a click on **Validate Syntax**.
    - **What is found:** mistakes in the SQL, a data extension or system data view that does not exist, and a field that does not exist in it, also for names written with `ENT.` or in brackets.
    - **How:** a moment after you stop typing, the extension sends the query to the request that the **Validate Syntax** button uses, through the page you are logged in to. Nothing is written by it. An answer for text that is no longer in the editor is dropped; an empty query and an unchanged one are not sent.
    - **Where:** a mark next to the line number, and an underline on every place the named field, data extension or view stands in the query, outside text in quotes and comments. Marketing Cloud's hints (a missing `WHERE`, `SELECT *`) are yellow at the line and column they name. Rest the mouse on the underline or on the mark to read Marketing Cloud's message in the extension's box, right at that place.
    - **Status instead of the button:** a status next to the **{ }** button, marked with the extension's icon, says what the check of the text in the editor came to: **Checking…** from the moment you change the text until the answer is shown, **No problems found**, or the counts, such as **1 error** or **2 errors, 1 hint**. It says nothing while the query is empty. Screen readers read it out when it changes.
    - **Validate Syntax is hidden** in the SQL query activity while the extension checks the query, because the status says the same. It stays while the query is empty, which is not checked. The button of the script activity stays.
    - **When Validate Syntax comes back:** when Marketing Cloud gives no usable answer (no connection, an error, an answer that cannot be read), the status says **Could not check** and the button is shown again; the same query is then sent again the next time you stop typing. The button is also back whenever the extension does not check the editor.
    - **Limits:** Marketing Cloud names one unknown field per check and gives no place for errors, so an error it does not tie to a name is marked at the start of the query. The read-only editor of the summary step is not checked.
    - The feature is always on and has no switch, and needs no new permission.
- **Delete in Mobile Studio**: MobileConnect lets no message be deleted, and neither app lets one be deleted from its list. The extension adds this, and with it deletes data on your click for the first time in these apps.
    - **MobileConnect, page of a message:** a **Delete** button in the header.
    - **MobileConnect and MobilePush, list of messages:** a checkbox in front of the name of each row, and a button **Delete selected (n)**. No column is added to the list, so the list itself works as before and a click on the name still opens the message. A click on the checkbox or right next to it never opens the message, and what is ticked is kept when the list is searched, sorted or paged, as long as the message is still shown.
    - **A question first:** a dialog of the extension names every message that will be deleted and, separately, every message that will not, with the reason. Nothing is sent before the click on **Delete n messages**.
    - **Read again, never trusted from the list:** every chosen message is read from Marketing Cloud before the question, and once more right before its delete. A message that changed meanwhile, or has another name than the one shown, is left alone.
    - **Refused, SMS:** a message that belongs to a transactional SMS message. Deleting it would leave that transactional message broken for good (seen on a real account). For this, every transactional SMS message of the business unit is read once per dialog; if they cannot all be read, the message is refused too. Transactional messages that Marketing Cloud says no longer exist are passed over.
    - **Refused, push:** a message triggered by the API that has the name of a transactional push message, and every active push message, however it is sent (make it inactive first). Drafts and inactive ones are deleted.
    - **Refused, both:** a message a journey made, and any message whose answer from Marketing Cloud lacks what the check needs.
    - **A link to the transactional message:** in both apps, a message refused because of a transactional message has the link **Open the transactional message**, which closes the dialog and opens the panel Transactional Messages on that message. Several transactional messages with the same name get a link each, with the key.
    - **A link that looks for the journey:** in both apps, a message a journey made has the link **Find the journey**. Only the click reads the journeys, in all their versions, once for all messages of the dialog; the dialog says how far it is. Every journey version that uses the message gets a link that opens it in a new tab.
    - **A journey's message that no journey uses any more may be deleted:** when the search read every journey version and none names the message, it moves to **Will be deleted**, although it is active (tried on a real account for a push and for an SMS message: the journey was deleted, its message stayed, and deleting it changed nothing else). The list of journeys comes in no fixed order, so it is read again, three times at most, while a version is missing. The journeys are read again right before the delete. If they cannot be read completely, or belong to another business unit than MobilePush is in, the message stays refused. Of push messages, this holds for plain notifications only; an inbox or in-app message of a journey stays refused.
    - **How the journeys are read:** MobilePush may not read journeys, so the Marketing Cloud page reads them for it, page by page, through the page you are logged in to. Nothing is written by it and no new permission is needed.
    - **One after the other:** a delete that fails is shown with what Marketing Cloud said and does not stop the rest; at the end the dialog says how many were deleted and how many failed, and the list is loaded again.
    - **Not tried, and deleted without a special check:** scheduled or keyword-bound SMS messages, and push messages with automations, which the message itself does not show.
    - The extension therefore also runs on `https://mc.<stack>.marketingcloudapps.com/MobileConnectFuel3/` and `…/mobilepush/`, which needs no new permission. The feature is always on and has no switch.
- **Transactional messages, formatting the message:** the code editor of the form for an SMS or push message gets what the other code editors have: the **{ }** button, Shift+Alt+F, and formatting before the form is saved when that option is on. The details, which are only read, are never formatted. For this the formatter is loaded when such a form is opened.
- **Marketing Cloud Next, Handlebars in the content editor**: inside `{{ }}` the extension now helps as it does with AMPscript. Before, everything about Handlebars was left to the editor.
    - **Suggestions:** the helpers Marketing Cloud Next has, while you type a name and on **Ctrl+Space**. A helper is written with a blank after it. After `{{#` only helpers that open a block are offered, and nothing after `{{/`, `{{>` and `{{!`. While the editor shows its own list, ours stays away.
    - **Explanations:** rest the mouse on a helper and the extension's box explains it, with its inputs, an example, a link to its page on sfmc.guide and a note where Marketing Cloud Next differs from Salesforce's documentation. The editor's own box is hidden there, so there are never two. On a field inside `{{ }}`, which only the editor knows, the editor's box stays.
    - **Mistakes underlined:** a helper Marketing Cloud Next does not have, and a helper written in the wrong case (Marketing Cloud Next tells `properCase` from `propercase`), with a one-click fix that also corrects the closing tag of a block.
    - **Blocks:** a block closed with the wrong name is underlined at that name, and a block that is never closed at the name that opens it. An expression without its `}}` and an empty `{{ }}` are underlined at their opening braces. One such mistake no longer hides the others in the same content.
    - **Fields are left alone:** a field that has the name of a helper, such as `add` in `{{uppercase add}}`, is not explained as that helper, and no helper is suggested where a field goes.
    - Nothing changes in Marketing Cloud Engagement.
- **Transactional Messages, the lists of Mobile Studio follow a delete:** when a transactional message was deleted in the panel, also when it is not known whether the delete arrived, closing the panel loads the list of MobilePush or MobileConnect again, whichever shows the messages of that channel.
- **Transactional push, link to its content:** the details and the form of a transactional push message show **Open in Content Builder**, a link to the asset that holds the message, which opens in a new tab. For this the panel reads the business unit you are in once.
- **Links to a Content Builder asset**: Content Builder's address never changes, so an asset could not be sent as a link. Now it can, to anyone who has the extension.
    - **The address names the open asset:** while an asset is open, the address of the Marketing Cloud page ends with `#app/Content%20Builder/ux-tools/<mid>/asset/<id>`, the business unit's MID and the asset's id; back on the list, it is Content Builder's plain address again. The page is not loaded again for this.
    - **Back and Forward:** opening an asset by hand, and closing it, adds an entry to the browser's history. Back from an asset closes it and shows the list again; Forward opens it again, by the search and the click that follow a link, without loading Content Builder anew. You can step back and forward as often as you like: the extension shows such a step itself and keeps it from Marketing Cloud, whose reload of Content Builder made the next Back leave the app. A step to an asset of another business unit is left to Marketing Cloud and gets the dialog. Following a link, and whatever Content Builder does by itself, adds no entry.
    - **Following a link:** opened with the extension, such an address makes Content Builder search for the asset's name and open the row with that id. For this the extension reads the asset's id and name once from Marketing Cloud. Once the asset is open, the search box is emptied again; after a link that could not be followed it keeps the name.
    - **Another business unit:** a link of a business unit other than the one you are in is not searched for. A dialog of the extension names the link's business unit and yours, with **Switch and open** and **Stay here**. Nothing switches without the click.
    - **The dialog comes early and must be answered:** it is shown as soon as the business unit you are in is known, while Marketing Cloud loads behind it. The page is greyed out and blocked until a button is clicked; Escape and a click next to the dialog do not close it. A link is decided once.
    - **The business unit you are in** is taken from Marketing Cloud's API or from the header of the Marketing Cloud page, whichever is known first when the page is loaded. After about 10 seconds without either, it counts as unknown and the link is not followed.
    - **Another account:** when the link's business unit does not exist in the account you are logged in to, or you have no access to it, the dialog says so, with the name of that business unit and of its account if this browser was in it before.
    - **Business units the browser has seen:** for that hint, the extension keeps the ids and names of the business units of each account you open, in Chrome's extension storage on this computer only. The new button **Forget the business units this browser has seen** on the options page deletes the list.
    - **Requests:** on each load of the Marketing Cloud page, the extension reads the list of business units of the account and the business unit you are in, link or not, and it reads the business unit you are in again whenever it writes or follows a link.
    - **Without the extension** the address opens Content Builder as usual.
    - **When it fails:** when the search has not listed the asset after one minute (the first search on a freshly loaded page can take about half a minute), a note of the extension in Content Builder names the asset's id and can be closed. Nothing is tried again.
    - **Limits:** only assets that the business unit's own search lists (not shared content of another business unit); the search lists 30 assets at most, so a very common name can leave the asset out; the asset opens as by a click in the list, not in the editor; Content Builder inside Email Studio's Content tab gets no link.
    - **Tried on a real account:** writing the address, following a link with the search emptied afterwards, the dialog in another business unit, and **Switch and open**.
    - It changes nothing in Marketing Cloud and needs no new permission. The feature is always on and has no switch.
- **Links into Email Studio**: an address of Email Studio only ever opened the section, with an empty page. With the extension it opens the view.

For each of them, writing the address and following the link from a freshly loaded page were tried on a real account. When Email Studio's address holds the route already, setting it would change nothing, so the route is handed to the route reader of Email Studio's own library instead. A click or a key press in Email Studio ends this at once; until then, or until the tries are used up, the address keeps the link.
    - **Another business unit or account:** the same dialog as for links to an asset, which now speaks of "this link" under the heading **Link to another business unit**. **Switch and open** goes to the plain address of the app in the other business unit, for both apps; the link itself is kept in the tab's session storage and taken once by the Marketing Cloud page that opens after the switch, which follows it only when it opens the app of the link. The dialog and **Switch and open** were tried on a real account for the data extension.
    - **Without the extension** the address opens Email Studio at the section.
    - **Limits:** one group, one data filter, All Subscribers, everything in Content, Interactions, Tracking and A/B Testing, and the older pages (such as Admin) get no link, and neither does anything inside a view (paging, sorting, wizard steps, pop-ups). A link names a route from a fixed list only, never an address.

The extension now runs two more scripts in Email Studio's frame (`https://*.exacttarget.com/C12/Default.aspx`), one of them in the page's own script world to see what Email Studio shows. The feature is always on and has no switch.

Without a route it is Contact Builder's plain address again. The page is not loaded or routed again for this, and nothing is done on a clock.

On such a step the extension asks Contact Builder's frame to show the route, by writing it over the route in the frame's own address, and keeps the step from Marketing Cloud, which lost the entries after it (Forward did nothing). The tab highlighted in the bar at the top is set to the one that was highlighted when that route was opened by hand. The first route of a visit, and routes that Contact Builder moves on to by itself, add none.
    - **Works without the extension:** this is the form that Marketing Cloud opens by itself, with the complete Contact Builder interface. The extra field `ux-tools=<mid>` was tried on a real account: the link still opens the data extension.
    - **Another business unit or account:** with the extension, a link whose MID is another business unit gets the same dialog as the links to an asset, with **Switch and open** and **Stay here**; **Switch and open** carries the link across the switch. A link without the field is not checked.

So while a link is not known to belong to the business unit the user is in, its route is taken out of the address before Marketing Cloud reads it, and nothing is written into the address until the user is known to be in the right business unit or answered the dialog. **Stay here** leaves plain Contact Builder open, and the address follows it from then on. ### Fixed

- **Format on save and Ctrl+S in Content Builder saved outdated code**: Content Builder saves its own copy of the code, and copies a change from the editor only about half a second after it was made.
    - **Format on save:** the save was let through 0.3 seconds after the formatting, so the code from before the formatting was stored while the editor showed the formatted code as **Saved**.
    - **Ctrl+S:** pressed right after typing, the save could miss the last words.
    - **Now** a save waits until Content Builder says that it has taken over what the editor shows. If it says nothing for three seconds, the save goes through anyway.
- **Formatting:** a short AMPscript expression inside text, such as `%%=v(@code)=%%` in an SMS, stays on one line instead of being spread over three. Comes with the bundled formatter (`prettier-plugin-sfmc` 2.3.1).
- **Suggestions in Marketing Cloud Next:** the extension's icon in the list of suggestions has a column of its own at the right edge. Before, it lay on top of the first suggestion.
- **Delete in MobileConnect:** the checkboxes and the **Delete selected** button were missing when Marketing Cloud opened MobileConnect under an address in small letters, which it does at times. They are there now.
- **Options:** when the options are higher than the popup, only the vertical scroll bar appears. The page now leaves room for it; before, that scroll bar made the page too wide and brought a horizontal one as well.

## [1.0.0] - 2026-11-20

First release in the Chrome Web Store.

### Changed

- Chrome 122 or newer is required.
- Email Studio and CloudPages are named as covered: both open Content Builder's code view, where the extension already works.
- The toolbar icon is no longer greyed out, and a click on it opens the options.
- The options are twice as wide and show their settings in two columns, so that they fit the popup without scrolling.
- The options end with a copyright note and a link to the issues on GitHub for questions and problems.
- The editor theme follows the system's light or dark mode until a theme is chosen in the options; "Like the system" is the new default there.
- The gear button below the code editor, which opens Marketing Cloud's own editor menu, is hidden while the browser's context menu is chosen (the default), and comes back with the option "Marketing Cloud's menu".

### Added
